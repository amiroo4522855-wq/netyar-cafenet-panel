# کافی نت نت یار — NetYar Internet Cafe

![Node](https://img.shields.io/badge/Node.js-%E2%89%A518.17-3c873a)
![Dependencies](https://img.shields.io/badge/dependencies-0-brightgreen)
![Sites](https://img.shields.io/badge/sites-688-0a84d6)
![License](https://img.shields.io/badge/license-UNLICENSED-lightgrey)


پنل حرفه‌ای و سریع دسترسی به **سامانه‌ها و خدمات دیجیتال ایران**؛ مجموعه‌ای از
سامانه‌های دولتی، بانکی، قضایی، آموزشی، بیمه، مالیاتی، درمانی، حمل‌ونقل، شهرداری و
کسب‌وکار در یک رابط کاربری مدرن، دوزبانه (فارسی/لاتین) و راست‌به‌چپ.

> **هدف طراحی:** مینیمالیسم در سطح محصولات تجاری رده‌بالا + سرعت + دقت اطلاعات.
> هیچ داده ساختگی، لینک جعلی یا دکمه تزئینی در این پروژه وجود ندارد.

## ۲) اجرای پروژه

پیش‌نیاز: **Node.js نسخه ۱۸.۱۷ یا بالاتر**. هیچ وابستگی npm ندارد (`npm install` لازم نیست).

```bash
cd netyar
npm start            # یا: node server/index.js
```

سپس در مرورگر: `http://localhost:3000`

رمز ورود پیش‌فرض در اولین اجرا از متغیر محیطی خوانده و **فقط به‌صورت هش scrypt**
در `server/.credentials.json` ذخیره می‌شود:

```bash
NETYAR_ACCESS_CODE='5581' npm start
```

### متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `3000` | پورت سرور |
| `HOST` | `0.0.0.0` | آدرس bind (برای preview باید `0.0.0.0` باشد) |
| `NETYAR_ACCESS_CODE` | `5581` | رمز ورود؛ فقط در **اولین اجرا** خوانده و هش می‌شود |
| `NETYAR_SESSION_SECRET` | تصادفی | کلید امضای کوکی نشست (در `server/.secret.key` ذخیره می‌شود) |
| `NETYAR_ADMIN_KEY` | *(خالی = خاموش)* | فعال‌سازی API مدیریت؛ در هدر `X-Admin-Key` ارسال می‌شود |

> **تغییر رمز ورود:** فایل `server/.credentials.json` را حذف کنید و سرور را با
> `NETYAR_ACCESS_CODE` جدید اجرا کنید.

### اسکریپت‌ها

```bash
npm run discover    # کشف دامنه‌های واقعی از لاگ گواهی‌نامه‌ها (crt.sh)
npm run verify      # اعتبارسنجی DNS + CT + favicon و دریافت لوگوها
npm run icons       # گذر سریع تکمیلی برای لوگوها
npm run build:data  # تولید data/sites.json از داده‌های کیوریت‌شده + نتایج اعتبارسنجی
npm run audit       # ممیزی کیفیت دیتاست (تکراری، فیلد خالی، لوگوی مفقود، …)
npm test            # ۲۴ آزمون خودکار (احراز هویت، API، امنیت، دیتاست)
```

## ۵) مرجع API

همه پاسخ‌ها JSON هستند. مسیرهای غیر از `/api/health` و `/api/auth/*` و `/api/session`
نیاز به نشست معتبر دارند.

| متد | مسیر | توضیح |
|---|---|---|
| `GET` | `/api/health` | وضعیت سرور، تعداد سایت‌ها، زمان پاسخ |
| `GET` | `/api/session` | آیا کاربر وارد شده است؟ |
| `POST` | `/api/auth/login` | `{ "accessCode": "…" }` → کوکی نشست HttpOnly |
| `POST` | `/api/auth/logout` | پایان نشست |
| `GET` | `/api/catalog` | کل کاتالوگ (gzip + ETag + `304`) |
| `GET` | `/api/me` | کاربر + محبوب‌ها + اخیرها + ترجیحات |
| `GET` | `/api/me/favorites` | فهرست شناسه محبوب‌ها |
| `PUT` | `/api/me/favorites` | `{ "ids": [1,2,3] }` جایگزینی کامل |
| `POST` | `/api/me/favorites/toggle` | `{ "id": 12 }` افزودن/حذف |
| `POST` | `/api/me/recents` | `{ "id": 12 }` ثبت بازدید |
| `PUT` | `/api/me/prefs` | `{ "theme": "dark", "density": "compact" }` |
| `GET` | `/api/admin/sites` | 🔐 فهرست (نیازمند `X-Admin-Key`) |
| `POST` | `/api/admin/sites` | 🔐 افزودن سایت |
| `PATCH` | `/api/admin/sites/:id` | 🔐 ویرایش سایت |
| `DELETE` | `/api/admin/sites/:id` | 🔐 حذف سایت |
| `POST` | `/api/admin/categories` | 🔐 ساخت دسته‌بندی |

**کدهای خطا:** `400` ورودی نامعتبر · `401` احراز هویت · `403` دسترسی ممنوع ·
`404` یافت نشد · `405` متد مجاز نیست · `413` بدنه بزرگ · `429` محدودسازی نرخ · `500` خطای سرور

### نمونه: افزودن سایت با API مدیریت

```bash
curl -X POST http://localhost:3000/api/admin/sites \
  -H 'Content-Type: application/json' \
  -H 'X-Admin-Key: <کلید>' \
  -b cookies.txt \
  -d '{"name":"سامانه نمونه","organization":"سازمان نمونه","category":"gov",
       "description":"توضیح کوتاه","url":"https://example.ir","featured":true}'
```

> ویرایش‌ها و افزودنی‌های مدیر در `data/admin-overrides.json` ذخیره می‌شوند و
> هنگام ساخت کاتالوگ روی دیتاست پایه اعمال می‌گردند — یعنی بدون دست‌کاری فایل اصلی.

## ۶) امنیت

| مورد | پیاده‌سازی |
|---|---|
| **احراز هویت** | سمت سرور؛ رمز هرگز به کلاینت ارسال یا در آن ذخیره نمی‌شود |
| **ذخیره رمز** | `scrypt` (N=16384, r=8, p=1) با salt تصادفی ۱۶ بایتی، در فایلی با دسترسی `0600` |
| **مقایسه رمز** | `crypto.timingSafeEqual` (مقاوم در برابر timing attack) |
| **نشست** | کوکی `HttpOnly` + `SameSite=Strict` + امضای `HMAC-SHA256` + انقضا ۱۲ ساعته + `Secure` در HTTPS |
| **Rate Limiting** | ۸ تلاش ناموفق → قفل ۱۵ دقیقه‌ای بر اساس IP، با هدر `Retry-After` |
| **اعتبارسنجی ورودی** | ماژول `V` در `server/http.js` (طول، نوع، الگو، URL، آرایه، شناسه) |
| **XSS** | فرار کامل همه داده‌ها با `esc()` در کلاینت + رندر فقط از طریق `textContent`/قالب فرار‌شده |
| **CSP** | `default-src 'self'` · `script-src 'self'` · `img-src 'self' data:` · `frame-ancestors 'none'` · `object-src 'none'` |
| **سایر هدرها** | `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, `COOP/CORP`, `HSTS` روی HTTPS |
| **Path traversal** | بررسی مسیر قبل از سرو فایل + رد درخواست‌های دارای `..` و `\0` |
| **لینک خروجی** | `rel="noopener noreferrer nofollow"` + `target="_blank"` |
| **حجم بدنه** | سقف ۶۴ کیلوبایت برای همه درخواست‌های JSON |

## ۷) روش اعتبارسنجی دامنه‌ها (بدون حدس)

از آنجا که از محیط توسعه، اتصال TCP مستقیم به IPهای داخل ایران ممکن نبود،
هر دامنه با **سه سیگنال مستقل و واقعی** بررسی شد:

1. **DNS** — ریزالو سیستم + DNS-over-HTTPS (Google و Cloudflare). اگر دامنه
   `NXDOMAIN` بود، **حذف** شد.
2. **Certificate Transparency** — پرس‌وجوی `crt.sh` برای دامنه و اَبَکس آن.
   وجود گواهی TLS یعنی آن دامنه واقعاً سرویس HTTPS داشته است. همین روش برای
   **کشف** ۴٬۱۴۲ زیردامنه واقعی (مانند واحدهای دانشگاه آزاد، خدمات شهرداری تهران،
   درگاه‌های بانک ملت و شرکت‌های پرداخت شاپرک) استفاده شد.
3. **Favicon** — دریافت لوگوی واقعی از `favicon.im` و `Google S2`. fallbackهای
   عمومی این سرویس‌ها (آیکون خاکستری «f»، لوگوی unavatar، placeholder گوگل)
   با بررسی محتوا و اندازه **رد** شدند تا لوگوی جعلی وارد پروژه نشود.

**نتیجه:**

| شاخص | مقدار |
|---|---|
| دامنه‌های بررسی‌شده | ۷۸۵ + ۴٬۱۴۲ نام کشف‌شده از CT |
| دامنه‌های ردشده (DNS ناموفق و بدون گواهی) | **۲۵۲** — همه حذف شدند |
| رکوردهای نهایی | **۶۸۸** |
| با DNS تأییدشده | ۳۴۵ |
| با گواهی TLS تأییدشده (crt.sh) | ۱۰ |
| با لوگوی واقعی (favicon) | ۳۱۷ |
| با مونوگرام تولیدشده (fallback تمیز) | ۳۷۱ |
| تکراری حذف‌شده در ممیزی | ۱۱ دامنه هم‌نام |

### صادقانه درباره محدودیت‌ها

* **پاسخ HTTP مستقیم سایت‌ها تست نشد** (مسدود بودن مسیر شبکه از محیط توسعه به
  IPهای ایرانی). به همین دلیل فیلد `https` فقط وقتی `true` است که گواهی TLS یا
  favicon واقعی پیدا شده باشد؛ در غیر این صورت `false` است و در مودال جزئیات،
  نشان «بدون تأیید HTTPS» نمایش داده می‌شود.
* **تصویر/Thumbnail سایت‌ها** عمداً `null` گذاشته شد: هیچ منبع معتبری برای
  اسکرین‌شات رسمی این سامانه‌ها در دسترس نبود و طبق صورت مسئله، تصویر ساختگی
  جایگزین آن نشد.
* **لوگوی ۳۷۱ سایت** از سرویس‌های favicon قابل دریافت نبود (بسیاری از سامانه‌های
  دولتی از ابرهای عمومی مسدود هستند). برای این موارد مونوگرام حرف اول با
  گرادیان رنگی **تولید محلی** می‌شود — بدون هیچ تصویر جعلی.
* فهرست ۲۵۲ دامنه ردشده در `data/report.json` (کلید `rejectedDomains`) ثبت شده
  تا قابل بازبینی باشد. برخی از آن‌ها صرفاً از این محیط قابل resolve نبودند و
  ممکن است در شبکه داخل ایران فعال باشند؛ در صورت نیاز می‌توانید آن‌ها را
  دوباره به `data/candidates.tsv` اضافه و `npm run verify && npm run build:data`
  را اجرا کنید.

## ۸) معماری آماده برای توسعه

* **لایه داده جدا** — همه دسترسی‌ها از `server/store.js` عبور می‌کنند؛ برای مهاجرت
  به PostgreSQL/SQLite کافی است فقط همین ماژول بازنویسی شود.
* **پوشش تغییرات مدیر** — `admin-overrides.json` به‌جای دست‌کاری دیتاست پایه.
* **API مدیریت کامل** — افزودن/ویرایش/حذف سایت، featured کردن، تغییر لوگو،
  توضیح، نشانی و ساخت دسته‌بندی.
* **لایه API کلاینت** — همه فراخوانی‌ها در `public/js/api.js` متمرکز است.
* **دیتاست توسعه‌پذیر** — افزودن سایت جدید فقط یک خط در `data/meta.js` و اجرای
  `npm run build:data` است.

## ۹) تست و ممیزی

```bash
npm test        # ۲۴ آزمون: همه سبز
npm run audit   # ممیزی دیتاست: ۰ مشکل
```

آزمون‌ها این موارد را پوشش می‌دهند: ورود با رمز درست/غلط، HttpOnly بودن کوکی،
قفل بودن کاتالوگ بدون ورود، عدم نشت رمز در فایل‌های فرانت‌اند، هدرهای امنیتی،
عدم سرو فایل‌های بیرون از `public`، CRUD محبوب‌ها/اخیرها/ترجیحات، رد شدن ورودی
نامعتبر، CRUD کامل پنل مدیریت، خروج، یکپارچگی دیتاست (فیلد خالی، دامنه تکراری،
نشانی بدساخت، لوگوی مفقود)، صحت تبدیل تاریخ جلالی، gzip و Rate Limiting.

## ۹٫۵) فعال‌سازی گردش‌کار CI (اختیاری)

فایل آماده در `docs/github-actions-ci.yml` قرار دارد (بازسازی دیتاست + ممیزی +
۲۴ آزمون روی Node ۲۰ و ۲۲ در هر push و pull request). برای فعال‌سازی:

```bash
mkdir -p .github/workflows
cp docs/github-actions-ci.yml .github/workflows/ci.yml
git add .github && git commit -m "ci: فعال‌سازی گردش‌کار آزمون" && git push
```

> انتقال این فایل با `gh auth login` معمولی ممکن نیست؛ گیت‌هاب برای ساخت یا ویرایش
> `.github/workflows/**` دامنه `workflow` می‌خواهد. یا با
> `gh auth login --scopes workflow` دوباره وارد شوید، یا از PAT با مجوز
> **Workflows: Read/Write** استفاده کنید، یا فایل را از وب‌اپ گیت‌هاب بسازید.

## ۱۱) هویت بصری

* **رنگ‌ها:** مشکی مات (`#08090c`)، سفید، آبی یخی (`#6fc7ff` / `#0a84d6`)،
  سبز زمردی (`#2ec4b2` / `#0f9d84`) و خاکستری‌های ظریف برای سطوح ثانویه.

  با `blur` کنترل‌شده و مرزهای نرم.

* **آیکون‌ها:** ۱۰۵ آیکون SVG درون‌خطی با استروک ۱.۶ و شبکه ۲۴×۲۴ —
  بدون Emoji و بدون کتابخانه خارجی.
* **لوگوی NetYar:** ترکیب حرف N با مسیر شبکه و یک گره داده (نقطه)، با گرادیان
  زمردی→یخی؛ حس فناوری + اعتماد + سرعت.
